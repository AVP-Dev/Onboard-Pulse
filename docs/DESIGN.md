- [x] ❓ **Q2 — Границы детекции проблем и правило закрытия:** Как однозначно выявлять критические сигналы и когда закрывать проблему?
  ➡️ **Рекомендация агента:** Детерминированный Rule Engine без LLM:
  - Оценка 1 или 2 по любой категории → `CRITICAL` (Критический сигнал).
  - Оценка 3 → `ATTENTION` (Сигнал внимания).
  - Оценка 4 или 5 → `NORMAL`.
  - Машина состояний проблемы: `NEW` → `IN_PROGRESS` (назначено действие и ответственный) → `PENDING_VERIFICATION` (ответственный отметил выполнение) → `CLOSED` или `IN_PROGRESS`.
  - **Инвариант закрытия:** Проблема переводится в `CLOSED` **ТОЛЬКО** при успешной повторной проверке (оценка сотрудника по данной категории >= 4). При оценке <= 3 статус возвращается в `IN_PROGRESS` с сохранением полного аудита.
  *(Статус: Согласовано)*

- [x] ❓ **Q3 — Токены анкет и предотвращение повторной отправки:**
  ➡️ **Рекомендация агента:** Криптографически стойкие UUIDv4 токены в SQLite. Флаг `is_completed`, timestamp `completed_at`, одноразовое использование. Повторный `POST` по уже завершенному токену отклоняется с кодом 409 Conflict / 400 Bad Request.
  *(Статус: Согласовано)*

## 1. Метаданные и скоуп

- **Затронутые модули:**
  - `src/db/` — схема, миграции, репозиторий SQLite (`node:sqlite`), синтетический seed (демо-данные сотрудников).
  - `src/lib/` — машина состояний, rule engine, валидация DTO, сервисы HR и опросов.
  - `src/app/` — Next.js 16+ App Router:
    - `/` — HR Dashboard (аналитика подразделений/категорий, воронка проблем, реестр).
    - `/employees/[id]` — карточка сотрудника с историей пульс-опросов и открытыми проблемами.
    - `/issues/[id]` — карточка проблемы, назначение корректирующего действия, аудит-лог, повторная верификация.
    - `/survey/[token]` — mobile-first адаптивная анкета новичка (5 шкал, комментарий).
    - `/api/...` — строгие Server Actions и Route Handlers с валидацией.
- **File ownership / scope:** Полная изоляция бизнес-логики в `src/lib`, разделение представления и данных.
- **Делегирование:** Zone 1 (UI, валидаторы, конвертеры) + Zone 2 (Server Actions, State Machine, SQLite Repository). Zone 3 параметры зафиксированы в настоящем манифесте.
- **Topology:** `single`
- **Рабочие гипотезы:** Быстрое выявление проблем новичков на ранних этапах (первые 90 дней) снижает текучесть кадров на складе, в рознице, продажах и офисе.
- **Цель:** Полнофункциональный MVP автономной системы с полным жизненным циклом от регистрации новичка до подтверждённого закрытия проблем.
- **Rollback / stop plan:** Изолированная локальная база SQLite в файле `data/pulse.db`, откат транзакций при сбоях.

## 2. Инварианты системы (Invariants)

1. **Одноразовость анкеты (Single-Use Token Invariant):** Анкета по токену может быть отправлена ровно 1 раз. После заполнения токен немедленно помечается завершенным. Повторные отправки невозможны ни при каких условиях.
2. **Отсутствие дублирования открытых проблем (No Duplicate Open Issues):** Для пары `(employee_id, category)` в статусах `NEW`, `IN_PROGRESS`, `PENDING_VERIFICATION` не создается повторный дубликат проблемы; последующие низкие оценки дополняют контекст существующей открытой проблемы.
3. **Строгий инвариант закрытия проблемы (Verified Closure Invariant):** Проблема не может быть закрыта ни HR, ни ответственным без подтвержденной успешной повторной проверки сотрудника (re-check survey score >= 4).
4. **Безопасность и отсутствие реальных ПДн (Synthetic Privacy Invariant):** Система оперирует исключительно синтетическими профилями и не передает данные во внешние контуры.
5. **Детерминированность правил (No LLM in HR Decisions):** Анализ оценок и категоризация проблем проводятся прозрачными правилами без недетерминированных нейросетевых галлюцинаций.
6. **Персистентность данных (Persistence Invariant):** Данные сохраняются в надежный файл SQLite на диске (`data/pulse.db`) и не теряются при перезапуске сервера.

## 3. Конечный автомат (State Machine)

### 3.1. Статусы опроса (Survey Token)
- `PENDING` (создан, ожидает заполнения)
- `COMPLETED` (успешно отправлен, сохранены ответы)
- `EXPIRED` (истёк срок действия)
*Запрещен переход:* `COMPLETED` → `PENDING`.

### 3.2. Статусы проблемы (Issue Lifecycle)
```
          [Низкая оценка 1-3]
                  │
                  ▼
              ┌──────┐
              │ NEW  │ (Обнаружена сигнальная проблема)
              └──┬───┘
                 │ HR назначает ответственного и план действий
                 ▼
         ┌───────────────┐
         │  IN_PROGRESS  │◄─────────────────────────────┐
         └───────┬───────┘                              │
                 │ Ответственный выполнил действие      │
                 ▼                                      │ Оценка re-check <= 3
     ┌────────────────────────┐                         │ (Проблема осталась)
     │  PENDING_VERIFICATION  │                         │
     └───────────┬────────────┘                         │
                 │ Проводится повторный опрос (re-check)│
                 ├──────────────────────────────────────┘
                 │
                 │ Оценка re-check >= 4 (Подтверждено решение)
                 ▼
            ┌─────────┐
            │ CLOSED  │ (Проблема закрыта)
            └─────────┘
```
- **Недопустимые переходы:**
  - `NEW` → `CLOSED` (запрещено закрывать без действий и проверки).
  - `IN_PROGRESS` → `CLOSED` (запрещено без верификации).
  - `PENDING_VERIFICATION` → `CLOSED` если оценка повторной проверки < 4.

## 4. Границы сбоев (Failure Modes & Idempotency)

- **Конкурентные отправки анкеты:** SQLite `BEGIN IMMEDIATE` транзакция с проверкой `is_completed = 0` перед `UPDATE`.
- **Невалидные входные данные:** Валидация типов на входе: оценка strictly integer 1..5, длина комментария до 2000 символов. Отклонение с кодом 400.
- **Ошибки базы данных:** Fail-closed, возврат типизированного ответа с деталями для логов и нейтральным сообщением для пользователя.

## 6. Acceptance Invariants & Automated Verification Gate

1. **Rule Engine Unit Tests:**
   - Оценки 1, 2 формируют `CRITICAL`.
   - Оценка 3 формирует `ATTENTION`.
   - Оценки 4, 5 не формируют проблем.
2. **Single-Use Survey Invariant Test:**
   - Первая отправка возвращает 200/успех.
   - Повторная отправка с тем же токеном возвращает ошибку 409/400.
3. **Verified Closure Invariant Test:**
   - Попытка закрыть проблему с повторной оценкой 1..3 отклоняется, статус возвращается в `IN_PROGRESS`.
   - Повторная оценка 4..5 переводит проблему в `CLOSED`.
4. **Idempotency / No-Duplicate Test:**
   - Две подряд низкие оценки по одной категории не плодят несколько открытых проблем.
5. **Persistence Test:**
   - Данные, записанные в SQLite, читаются после переинициализации инстанса БД.
6. **Full Lifecycle Integration Test:**
   - Регистрация новичка -> генерация токена -> прохождение опроса -> появление проблем в HR-панели -> назначение плана -> завершение действия -> контрольный опрос -> верифицированное закрытие.
